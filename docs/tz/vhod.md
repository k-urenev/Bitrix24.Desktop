# Вход

Часть [технического задания](../tz.md). Портал, ключи, логин, OAuth, выход и протухшая сессия.

Окно «Вход в Битрикс24», ширина 480 px, минимум 420 px, высота по содержимому. Отступ формы 32 px. Фон `#E7F3FB`, кнопка «Войти» на всю ширину, цвет `#00ACE3`, белый текст. Снимок: [login.png](../mockup/login.png). На снимке действующая форма: заголовок «Битрикс24», кнопка «Войти», ссылка «Настройка портала». Строка «Подключение к порталу уже настроено» и фраза, что пароль не сохраняется, относятся к прежней программе. Для новой сборки они заменяются правилом ниже.

Портала по умолчанию нет. При первом запуске пользователь сам вводит адрес портала, код приложения и секретный ключ. Поля видны сразу, без заранее подставленного адреса:

- «Адрес портала»;
- «Код приложения»;
- «Секретный ключ»;
- «Логин»;
- «Пароль».

Над полями свёрнутая строка «Где взять код и секретный ключ», цвет `#959CA4`. Щелчок раскрывает инструкцию: код и секрет один раз создаёт администратор портала в разделе «Приложения → Разработчикам → Другое → Локальное приложение». Нужные права: чаты (`im`), задачи (`task`), пользователи (`user`), Push&Pull (`pull`). После смены прав пользователь входит снова. Это не логин и не пароль. Строка, инструкция, подписи, поля, ошибка и кнопка — 16 px. Заголовок «Битрикс24» — 24 px. Между подписью и её полем 4 px, между полями 8 px, над «Войти» 16 px. Подписи цветом `#959CA4` рисуются чётко, без серого размытия. Обводка полей `#D5DDE3`. Углы окна прямые.

Поля кода и секрета остаются. Токен для запросов портал выдаёт только приложению, которое на нём уже установлено: в обмене обязательны код и секрет этого приложения. Логин и пароль открывают страницу входа и сами токен не дают. У официального мессенджера код своего приложения был внутри программы, поэтому снаружи хватало адреса портала и входа. В этой сборке своего приложения нет, поэтому код и секрет вводит пользователь.

Адрес, код и секрет сохраняются. Логин и пароль тоже сохраняются и подставляются при следующем входе. Кнопка «Войти» использует сохранённые значения.

«Войти» сначала ищет IP-адрес введённого портала. Если адреса нет, на форме красным «IP-адрес портала не найден. Проверьте написание.», окно браузера не открывается. Если адрес нашёлся, обмен идёт через WebView2 на `https://{портал}/oauth/authorize/` с кодом приложения и случайным `state`. Окно браузера 960×720. Код авторизации читается из query или fragment, и только если `state` совпал. Загрузка этого адреса обрывается, код на чужой обработчик не уходит. Обмен идёт на сервер из `server_domain`, иначе на уже известный адрес обмена, иначе на `oauth.bitrix.info`. Профиль дочитывается через `user.current`. Если среды WebView2 нет, форма сообщает, что нужно установить Microsoft Edge WebView2, и остаётся на месте.

«Назад» возвращает форму. Следующее «Войти» снова ищет IP и, если он есть, загружает новый адрес в том же окне браузера: среда WebView2 второй раз не запускается. Если имя нашлось, а страница портала не открылась, это видно в окне браузера. Английское сообщение среды на форме не появляется. Закрытие окна входа, пока вход не завершён, завершает программу.

Выход останавливает опрос, закрывает карточки, прячет главное окно и возвращает форму входа. Адрес, код, секрет, логин и пароль остаются. Стираются только access- и refresh-токены.

Протухшая сессия останавливает опрос, стирает токены и открывает вход с текстом «Сессия истекла. Войдите снова.» Access-токен обновляется заранее, если до конца срока осталось меньше двух минут, и так же при старте, если сохранённый токен пуст или почти истёк.
