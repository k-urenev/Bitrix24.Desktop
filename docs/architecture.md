# Устройство

`App` создает каталог данных, журнал и один экземпляр процесса. `AppHost` собирает сессию, REST-клиент, SQLite и опросчик, затем открывает окно входа или главное окно.

Портала по умолчанию нет. Адрес, код приложения, секрет, логин и пароль вводит пользователь на форме входа; они сохраняются в `auth.bin`. Секрет в документацию не копируется.

Повторный запуск не создает второй процесс. Он показывает уже открытое окно чата или, если вход еще не выполнен, окно входа. Запуск с `--exit` просит этот экземпляр завершиться так же, как пункт «Выход» в трее: значок снимается, опрос останавливается, процесс закрывается.

## Окно и трей

Главное окно 1112×640, минимум 952×480. Слева рейка 72 px, колонка списка 400 px. Окно входа по ширине 480 px. Страница портала в нем открывается на 960×720. Если окно не помещается в рабочую область, оно ужимается и ставится по центру этой области.

Крестик главного окна его прячет. Процесс остается в трее. Меню трея: «Открыть», «Не беспокоить», «Выход». Двойной щелчок по иконке тоже открывает окно. «Выход» останавливает опрос и завершает программу.

На иконке бейдж по сумме непрочитанных. Число больше 99 показывается как «99+». Подсказка иконки — «Битрикс24», при включенном «Не беспокоить» с этой пометкой, и при ненулевом счетчике с числом непрочитанных. Длинная подсказка обрезается до 63 символов.

В шапке окна имя пользователя и строка состояния. Рейка слева: «Чаты», «Уведомления», «Настройки», «О программе», внизу «Выйти из аккаунта». Состояния опроса: «На связи», «На связи. Нет мгновенных сообщений», «На связи. Нет прав на задачи», «На связи. Нет мгновенных сообщений. Нет прав на задачи», «Нет связи с порталом», «Портал ограничил запросы, ждём», «Нужно войти снова».

## Поток данных

1. `PortalPoller` в фоне опрашивает портал. Если подошли оба срока, сначала идут чаты. Рядом `PullListener` держит соединение Push&Pull.
2. Список чатов приходит из `im.recent.list` и сохраняется в SQLite. Команда мессенджера из Push&Pull запускает этот запрос сразу. Если сигнала нет, тот же запрос повторяется каждые 15 секунд. Конфигурация канала берётся из `pull.config.get`: WebSocket по `websocket_secure`, а если он не поднимается — длинный опрос по `long_pooling_secure`. При открытии сохранённый логин заново проходит авторизацию, чтобы токен совпал с правами приложения на портале, и `scope` читает уже этот токен. Нет `pull` — канал не поднимается. Если связь рвётся уже во время работы, программа трижды пытается её вернуть. После третьей неудачи право pull снято до следующего открытия: остаётся интервал 15 секунд, в шапке «На связи. Нет мгновенных сообщений». Успешный опрос чатов эту строку на «На связи» не меняет. Право на портале это не удаляет: новый набор прав появляется после входа.
3. `MainViewModel.ApplyDialogs` обновляет левую колонку.
4. Открытый диалог читает сообщения через `im.dialog.messages.get`. Свои сообщения помечаются прочитанными через `im.dialog.read`.
5. Задачи, где пользователь постановщик, исполнитель, соисполнитель или наблюдатель, опрашиваются раз в 60 секунд через `tasks.task.list`: четыре запроса, вместе не больше 200 задач. Если метода нет в правах, следующий опрос задач откладывается на 10 минут, а в шапке остается «На связи. Нет прав на задачи». Если при этом нет и мгновенных сообщений, строка — «На связи. Нет мгновенных сообщений. Нет прав на задачи». Успешный ответ снова включает обычный интервал.

Опрос открытого диалога просит обновить ленту. Открытым считается выбранный диалог, пока главное окно видимо и не свернуто. Пока это окно еще и активно, карточка по нему не ставится и играет `new-message-2.mp3`. Сообщение из другого чата при активном окне играет `new-message-1.mp3` без карточки. Сообщение открытого диалога не занимает место среди трех карточек за проход. «Не беспокоить» в трее глушит карточки и звук. За один проход показывается не больше трех карточек из других диалогов. Первый успешный опрос чатов и первый успешный опрос задач только запоминают точку отсчета и ничего не всплывает.

Карточка сообщения не ставится на свое сообщение и на системное (автор с id 0). Для таких сообщений и для режима «Не беспокоить» курсор уведомления сдвигается сразу, звука нет. Курсор открытого диалога тоже сдвигается сразу. Если новых диалогов, кроме открытого, больше трех, лишние в этот проход не помечаются и ждут следующего опроса.

Сетевая ошибка оставляет в шапке «Нет связи с порталом» и повторяет тот же опрос по его обычному интервалу. Ограничение частоты сначала отрабатывается внутри клиента, до пяти попыток. Если портал так и не ответил, оба опроса ждут паузу, которую посчитал клиент, а если ее нет — 30 секунд. В шапке при этом «Портал ограничил запросы, ждём». Протухшая сессия останавливает опрос, стирает токены и возвращает окно входа с текстом «Сессия истекла. Войдите снова.»

Пустой текст чужого сообщения в карточке заменяется на «Новое сообщение». Пустой заголовок диалога — на «Сообщение», пустой заголовок задачи — на «Задача». Цитата в тексте карточки схлопывается в одну строку.

Задача дает карточку, если с прошлого снимка изменились статус, крайний срок, ответственный или число комментариев. Задача «без звука» карточку не дает и в ленту страницы не пишется, но снимок обновляется. Новая для снимка задача с датой создания не раньше прошлого опроса пишется как «Вам назначена задача», если пользователь исполнитель; «Вы поставили задачу», «Вы соисполнитель» или «Вы наблюдатель» — для остальных ролей. Более старая — как «Задача обновлена». В одном проходе показывается не больше трех таких карточек. Изменившиеся, но не показанные задачи в снимок не записываются и всплывут на следующем опросе. «Не беспокоить» карточки задач глушит и при этом записывает весь новый снимок, так что после снятия режима старые правки уже не всплывают. Те же карточки складываются на страницу «Уведомления», новая сверху, и остаются после перезапуска. Комментарий к задаче, которая уже есть в ленте, новую строку не добавляет: у существующей меняются текст («Оставлен комментарий»), время и пометка непрочитанного. Щелчок открывает карточку задачи в браузере: `https://{портал}/company/personal/user/{id}/tasks/task/view/{id задачи}/`.

## Уведомления

`NotificationWindow` не забирает фокус и стоит в правом нижнем углу рабочей области, с отступом 16 px. Тени нет, обводка 1 px одинаковая по контуру. Новая карточка встает над предыдущей. На экране одновременно не больше трех: четвертая убирает самую раннюю. Карточка живет 15 секунд. Если за эти 15 секунд указатель на экране не сдвинулся, срок один раз продлевается еще на 15 секунд. Пока главное окно активно, карточка не появляется: выбранный чат играет `new-message-2.mp3`, другой чат — `new-message-1.mp3`. Пока окно неактивно, чужое сообщение играет `new-message-1.mp3` и показывает карточку. Задача играет `reminder.mp3`. Своя отправка играет `send.mp3`.

Щелчок по карточке сообщения открывает этот диалог. Щелчок по карточке задачи открывает ее страницу в браузере. Крестик без рамки справа сверху убирает карточку и больше ничего не делает. Выход из аккаунта убирает все карточки.

## REST

Вызовы идут через `BitrixRestClient`: OAuth-токен подставляется в метод, при протухании обновляется refresh-токеном. Токен обновляется и заранее, если до конца его срока осталось меньше двух минут. Так же программа поступает при старте, если сохраненный access-токен уже пуст или почти истек.

| Метод | Зачем |
| --- | --- |
| `user.current` | Имя и id текущего пользователя |
| `im.recent.list` | Список диалогов и статус последнего сообщения |
| `im.dialog.messages.get` | Лента. Поля прочтения чужими здесь нет |
| `im.dialog.get` | `readed_list`: до какого сообщения собеседники дочитали |
| `im.message.add` | Текст |
| `im.v2.File.upload` | Файл до 20 МБ, base64 |
| `im.dialog.read` | Свой курсор прочтения |
| `disk.file.get` | Скачивание вложения |
| `tasks.task.list` | Задачи пользователя |
| `pull.config.get` | Адрес и каналы Push&Pull, чтобы новое сообщение не ждало опроса |

Ошибки пишутся в `app.log`. Необработанное исключение интерфейса остается в журнале и показывается строкой в окне, кроме аварийных `OutOfMemoryException` и `AccessViolationException`. Сбой старта показывает то же сообщение отдельным окном и завершает программу.

## Интерфейс

`MainWindow` держит список диалогов, ленту и поле ввода. Лента — `MessageItem`, строка списка — `DialogItem`. Текст сообщения рисует `MessageBody`, поле ввода — `EmojiBox`. Галочки прочтения рисует `ReceiptMark`.

Уведомления — отдельное окно `NotificationWindow`. Иконка трея получает бейдж по числу непрочитанных.
