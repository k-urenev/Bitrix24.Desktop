# Данные и вход

Каталог приложения: `%LocalAppData%\Bitrix24.Desktop`.

| Файл | Содержимое |
| --- | --- |
| `auth.bin` | Сессия, защищенная DPAPI текущего пользователя Windows |
| `app.db` | SQLite, журнал WAL |
| `app.log` | Журнал ошибок |
| `WebView2` | Профиль браузера окна входа |

В `auth.bin` лежат домен портала, код и секрет локального приложения, логин, пароль, access- и refresh-токены, срок access-токена, адреса REST и обмена токена, `member_id`, id и имя пользователя, флаг «Не беспокоить». Файл читается только под тем же пользователем Windows, который его записал. Секрет в документацию не копируется.

Портала по умолчанию нет. При первом запуске на форме сразу видны адрес портала, код приложения, секретный ключ, логин и пароль. Над полями инструкция, где администратор создаёт локальное приложение. Адрес, код, секрет, логин и пароль сохраняются и подставляются при следующем входе. Кнопка «Войти» использует эти значения.

«Войти» открывает WebView2 на `https://{портал}/oauth/authorize/` с кодом приложения и случайным `state`. Сохранённые логин и пароль подставляются на странице портала. Код авторизации читается из query или fragment адреса, и только если `state` совпал. Загрузка этого адреса обрывается, код на чужой обработчик не уходит. Обмен кода на токены идет на сервер из `server_domain`, иначе на уже известный адрес обмена, иначе на `oauth.bitrix.info`. Профиль дочитывается через `user.current`. Если среды WebView2 нет, форма сообщает, что нужно установить Microsoft Edge WebView2, и остается на месте.

«Назад» в браузере входа возвращает форму. Закрытие окна входа, пока вход не завершен, завершает программу.

Выход стирает только access- и refresh-токены и возвращает окно входа. Домен, код, секрет, логин, пароль, id, имя и «Не беспокоить» в `auth.bin` остаются. Опрос останавливается, карточки уведомлений закрываются, главное окно прячется.

`app.db` при выходе не очищается и не делится по пользователям портала. Это текущее ограничение: после смены аккаунта на том же пользователе Windows до следующего опроса видны прежние диалоги, кэш переписки и снимки задач. Базовая точка уведомлений тоже общая.

## Таблицы `app.db`

`dialogs` — строка списка: заголовок, превью, id и автор последнего сообщения, время, непрочитанные, тип, порядок, флаг `last_delivered` и курсор `others_read_message_id`. Аватар в таблицу не пишется. После запуска, пока портал не ответил, в списке нет фотографий, остаются цвет и инициалы.

`messages` — лента диалога. Вложения лежат в `files_json`. Первичный ключ — пара диалога и id сообщения. На диалог хранятся последние 400 сообщений, более старые удаляются при записи.

`dialog_cursors` — id последнего сообщения, о котором уже уведомляли, и id, до которого диалог помечен прочитанным локально.

`task_snapshots` — последний снимок задач. По разнице с новым опросом решаются уведомления. Окно сравнения задач захватывает лишние 10 минут, чтобы не пропустить правку на границе интервала. В снимке лежат заголовок, статус, крайний срок, ответственный, число комментариев, даты создания и изменения.

`app_flags` — служебные флаги. `messages_baseline` и `tasks_baseline` отмечают, что точка отсчета уведомлений уже записана. `tasks_polled_at` — время прошлого успешного опроса задач. Новая задача считается назначением, если ее дата создания не раньше этого времени.

Цитаты в тексте сообщения разбирает `QuoteText`: блок между линиями из дефисов или знаков равенства длиной от 20 символов, с необязательной шапкой «имя [время]». В пузыре цитата рисуется отдельной плашкой. В превью и уведомлении она пишется «[Цитата]», слова до неё и после неё остаются.

Текст портала перед показом нормализуется. `[USER=…]…[/USER]` превращается в ссылку `https://[домен]/company/personal/user/[id]/` с подписью-именем. В ленте теги `b`, `i`, `u`, `s` сохраняются и рисуются полужирным, курсивом, подчёркиванием и зачёркиванием; в превью диалога и уведомлении эти теги снимаются, имя из `[USER]` остаётся текстом. Теги `br`, `img`, `size`, `color`, `quote`, `font`, `p` снимаются. Блок `[code]…[/code]` в ленте остаётся и рисуется моноширинным на серой плашке; в превью диалога и уведомлении теги снимаются, текст кода остаётся в строке. `[URL]` в ленте остаётся для кликабельной ссылки, в однострочном превью показывается подпись. В одной строке списка повторные пробелы схлопываются.
